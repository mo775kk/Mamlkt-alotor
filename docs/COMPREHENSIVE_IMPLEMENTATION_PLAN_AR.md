# خطة تنفيذ شاملة — مملكة العطور

تاريخ إعداد الخطة: 2026-10-29  
المستودع: https://github.com/mo775kk/Mamlkt-alotor  
الموقع: https://mo775kk.github.io/Mamlkt-alotor/

هذه الخطة تجمع جميع الاقتراحات السابقة في مسار تنفيذي واحد. وجود كود أو اسم وظيفة في المستودع لا يعني أن الوظيفة اختُبرت على المتصفح أو أنها متصلة بقاعدة بيانات فعلية.

## قواعد لا يجوز تجاوزها

1. لا تخترع أسعارًا أو مخزونًا أو مصدرًا أو نوتات عطرية أو صورة منتج أصلية.
2. لا تعرض أي سجل يحتاج مراجعة على أنه متاح للبيع؛ يجب الفصل بين «موجود في الكتالوج» و«متاح بالمخزون».
3. لا تخلط سعر الزيت/الجرام بسعر العبوة الجاهزة أو سعر التركيب. نوع المنتج هو الذي يحدد شبكة السعر.
4. لا تخزن كلمات المرور أو مفاتيح سرية أو بيانات العملاء الخاصة في ملفات الواجهة العامة.
5. لا تضف طبقات CSS فوق بعضها. أي تغيير بصري يجب أن يُدمج في ملف التصميم الأساسي مع مراجعة قواعد التعارض.
6. كل وظيفة جديدة يجب أن تتعامل مع عناصر DOM الاختيارية بأمان، وتُختبر على الهاتف والكمبيوتر.
7. لا تحذف بيانات أو سجلات متشابهة تلقائيًا قبل التحقق من اختلاف النوع والمورد والكود.
8. لا تُعلن نجاح الاختبار أو النشر إلا بعد ظهور نتيجة ناجحة من GitHub Actions والتحقق من رابط النشر.

## خريطة الميزات المقترحة

| الميزة | المطلوب تنفيذه | معيار القبول |
|---|---|---|
| بطاقة هوية المنتج | اسم عربي/إنجليزي، الماركة ودار العطر، النوع، العائلة، الأحجام، السعر، المصدر، حالة المراجعة والتوفر | كل حقل غير معروف يظهر «غير محدد» ولا يُختلق |
| مستشار العطور | أسئلة عن الذوق والمناسبة والميزانية، ثم اقتراح منتجات موجودة فقط | لا يقترح منتجًا غير موجود في بيانات الكتالوج ولا يدّعي تطابقًا مؤكدًا |
| مصمم الهدايا | مناسبة، ميزانية، المنتجات، العبوة، بطاقة إهداء | السعر محسوب من مكونات مسعرة فقط، والمكونات غير المسعرة تظهر كبحاجة لتأكيد |
| تركيب حسب الطلب | العائلة العطرية، نوع الزيت، الحجم، العبوة، ملاحظات العميل | ملخص واضح قبل إرسال واتساب، دون ادعاء أن التركيبة مختبرة أو آمنة جلديًا |
| سجل طلبات المنتجات الناقصة | تسجيل مصطلح البحث غير الموجود وتاريخ الطلب وعدد مرات التكرار | تنبيه واضح أن التخزين المحلي يخص الجهاز فقط؛ المزامنة تحتاج خدمة خلفية |
| مقارنة العطور | اختيار منتجين أو أكثر ومقارنة النوع والعائلة والنوتات والأسعار المتاحة | مقارنة مبنية على البيانات المتوفرة فقط |
| بحث مرن | الاسم العربي والإنجليزي والاسم البديل والدار والمورد والعائلة | تطبيع المسافات والتشكيل وبعض اختلافات الكتابة، مع عرض النتائج الفعلية فقط |
| محاسبة التكلفة والربح | تكلفة المورد والعبوة والتغليف والشحن والضريبة والتكلفة النهائية وسعر البيع | بيانات التكلفة خاصة بالإدارة ولا تظهر في صفحة العميل |
| حالات المنتج | متاح، غير متاح، يحتاج مراجعة، السعر غير محدد | منع تأكيد طلب شراء لسجل غير معتمد دون تنبيه ومراجعة |
| ملخص واتساب | المنتجات والأحجام والكميات والسعر المؤكد والإجمالي وبيانات التوصيل | لا يضيف سعرًا مجهولًا إلى الإجمالي ولا يرسل بيانات سرية |
| حماية الإدارة | تسجيل دخول حقيقي وصلاحيات وقواعد بيانات آمنة | لا يعتمد على إخفاء زر أو كلمة مرور داخل JavaScript |
| التقارير | البحث، الطلبات، النواقص، المخزون، التكلفة والربح | يوضح مصدر الأرقام والفترة، ولا يسمي عداد الجهاز «إجمالي زوار الموقع» |
| تجربة الهاتف | أحجام خط وصور وأزرار ومسافات مناسبة وRTL/LTR | لا يوجد تداخل أو تمرير أفقي غير مقصود أو عناصر غير قابلة للنقر |
| تصميم موحد | ملف تصميم أساسي واحد مع متغيرات موحدة وحالات responsive | لا توجد طبقات ثيمات قديمة تتغلب على الثيم الحالي ولا CSS حقن مكرر |
| كتالوج للطباعة وQR | صفحة/نسخة طباعة من المنتجات المعتمدة وروابط/QR لكل منتج | لا تظهر الأسعار/المخزون غير المؤكد كحقائق |

## مراحل التنفيذ

### المرحلة الأولى — سلامة المتجر والبيانات
- فحص كل ملفات HTML وCSS وJavaScript وروابط الملفات ونسخ cache-buster.
- إصلاح أخطاء الاختبارات التي تمثل مشاكل فعلية؛ تحديث الاختبارات القديمة المتعارضة مع قرارات التصميم الحالية بدل تغيير المنتج لإرضائها.
- إزالة تعارضات التصميم من مصدرها، لا إضافة overrides جديدة.
- تدقيق المنتجات: المعرفات الفريدة، التكرار المحتمل، النوع، السعر، الصورة، المصدر، النوتات، التوفر وحالة المراجعة.
- إنشاء تقرير نقص قابل للتصدير مع الاحتفاظ بالبيانات الأصلية.

### المرحلة الثانية — وظائف العميل
- تحسين بطاقة التفاصيل وحالات التوفر والسعر.
- مراجعة البحث وتسجيل الطلبات الناقصة.
- إكمال المقارنة ومستشار العطور.
- إكمال مصمم الهدايا وطلب التركيب وملخص واتساب.
- توحيد رسائل الأخطاء والتحميل والنتائج الفارغة والتأكيدات.

### المرحلة الثالثة — الإدارة
- شاشة تدقيق البيانات والمنتجات التي تحتاج مراجعة.
- إدارة الصور والروابط والمصادر والأسماء البديلة.
- مراجعة تكلفة المورد وتكلفة العبوة والشحن والضريبة وسعر البيع والربح.
- تقارير المخزون والمبيعات بعد إدخال بيانات حقيقية.
- تصدير/استيراد JSON مع تحقق من البنية ونسخة احتياطية قبل الاستبدال.

### المرحلة الرابعة — المزامنة والأمان
- التأكد من إعدادات Supabase وسياسات RLS وصلاحيات المستخدمين.
- فصل بيانات العملاء والطلبات والتكلفة عن أي بيانات عامة.
- اختبار فشل الاتصال وإعادة المحاولة وعدم فقد البيانات.
- عدم نشر أسرار الخدمة في GitHub أو JavaScript العام.

### المرحلة الخامسة — الإطلاق
- تشغيل smoke checks وفحوص الروابط والبيانات.
- اختبار عرض الهاتف والكمبيوتر، تفاصيل المنتج، البحث، الطلب، الإدارة، المزامنة والعمل دون اتصال.
- فحص GitHub Actions والتحقق من Pages بعد انتهاء النشر.
- نشر ملخص واضح لما اجتاز الاختبار وما بقي يحتاج تدخلًا أو بيانات من صاحب المتجر.

## البيانات التي تحتاج تأكيدًا من المتجر

- قائمة المخزون الفعلي لكل صنف وكميته.
- أسعار المورد الحالية، كود الصنف، حجم العبوة، وتاريخ القائمة.
- تكلفة الزجاجات والعلب والتغليف والشحن الفعلية.
- المنتجات المتاحة للبيع وأسعارها النهائية لكل حجم.
- صور المنتجات الأصلية ومصادر النوتات العطرية الموثوقة.
- سياسة الشحن والاستبدال والاسترجاع وطرق الدفع وأوقات العمل.
- بيانات تسجيل الدخول الإدارية وأسماء المستخدمين المصرح لهم؛ لا تُرسل كلمات المرور داخل الملفات أو المحادثات.
- هل سيظل المتجر بدون سلة، أم ستعاد السلة؟ يجب اعتماد قرار واحد لأن واجهة السلة وطلب واتساب يجب ألا تتعارضا.

## حدود تقنية مهمة

- GitHub Pages ينشر ملفات ثابتة؛ لا ينشئ وحده قاعدة بيانات مشتركة أو جلسات إدارية آمنة.
- localStorage مناسب للتفضيلات والسجلات المحلية غير الحساسة، وليس لتوحيد بيانات المبيعات بين أجهزة متعددة.
- عدد الزيارات المحلي على جهاز واحد ليس عدد زوار الموقع الكلي.
- أي نوتة مرجعية لعطر معروف لا تثبت أن زيت مورد معين مطابق لذلك العطر. تبقى مطابقة الزيت للمصدر بحاجة إلى مراجعة منفصلة.
- نجاح فحص JavaScript الثابت لا يعادل اختبار واجهة حقيقيًا على جميع المتصفحات.

## سجل التنفيذ

- أُنشئ تقرير تدقيق أولي في `data/CATALOG_COMPLETENESS_AR.md`.
- رُبط التقرير بملف `README.md`.
- أظهر التدقيق السابق 286 سجلًا في `data/products.json`، منها 110 ready و143 oil و33 oriental؛ جميعها موسومة بحاجة مراجعة وقت الفحص، ولا يحتوي هذا الملف وقتها على نوتات مسجلة في حقول النوتات. يجب إعادة حساب هذه الأرقام بعد كل استيراد.
- آخر تشغيلين لفحوص GitHub كانا في حالة انتظار عند إعداد هذا الملف؛ لا يُعلن نجاح الفحوص حتى تظهر النتيجة النهائية.
